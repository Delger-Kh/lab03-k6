## 1. Чанарын сценарио

### 1.1 Performance сценарио — `/cart/add`

| Хэсэг | Агуулга |
|---|---|
| **Тойм** | `/cart/add` endpoint-ийн хариу хугацаа хэвийн ачаалалд хэдий хэмжээнд байгааг үнэлнэ |
| **Системийн төлөв** | Сервер хэвийн ажиллаж байгаа, алдаагүй, ачаалал даах чадвартай |
| **Орчны төлөв** | 20 VU тогтмол ачаалал, 1 минутын турш |
| **Гадаад өдөөлт** | Хэрэглэгч бараагаа сагсанд нэмнэ (`POST /cart/add`) |
| **Шаардлагатай хариу** | Сервер 200 статус, `{ok:true, items:N}` JSON буцаана |
| **Хэмжүүр** | p95 хариу хугацаа < 200мс |


### 1.2 Reliability сценарио — `/pay`

| Хэсэг | Агуулга |
|---|---|
| **Тойм** | `/pay` endpoint төлбөр хийх үед хэр олон удаа амжилтгүй болдгийг үнэлнэ |
| **Системийн төлөв** | Сервер ажиллаж байгаа, гэхдээ дотоод логикоороо ~5% магадлалтайгаар 500 алдаа буцаадаг |
| **Орчны төлөв** | 20 VU, 1 минутын турш |
| **Гадаад өдөөлт** | Хэрэглэгч төлбөрөө баталгаажуулна (`POST /pay`) |
| **Шаардлагатай хариу** | Ихэнх хүсэлт амжилттай (`{paid:true}`), зарим нь gateway timeout алдаатай байж болно |
| **Хэмжүүр** | Error rate < 8% (POFOD) |



### 1.3 Availability сценарио — сервер crash

| Хэсэг | Агуулга |
|---|---|
| **Тойм** | Сервер гэнэт унаж, 10 секундийн дараа дахин асахад системийн боломжит хугацаа хэр их хадгалагдахыг үнэлнэ |
| **Системийн төлөв** | Ачаалалтай үед сервер процесс гэнэт зогсоно (crash) |
| **Орчны төлөв** | 10 VU, 2 минутын турш, дунд нь 10 секунд сервер унасан |
| **Гадаад өдөөлт** | Сервер crash хийж, дараа нь дахин асна |
| **Шаардлагатай хариу** | Сервер дахин асаад хэвийн хариу буцаах руугаа шилжинэ; зогсолтын үед хүсэлт амжилтгүй болно |
| **Хэмжүүр** | Availability ≥ 90%, сэргэх хугацаа ≈ 10с |

## 2. SLO хүснэгт

| Сценарио | SLI (юуг хэмжих) | Босго | Цонх / нөхцөл |
|---|---|---|---|
| Performance | `/cart/add` latency | p95 < 200мс | 20 VU тогтмол ачаалалд, 1 мин |
| Reliability | `/pay` error rate | < 8% | 1 мин, 20 VU |
| Availability | Бүх хүсэлтийн амжилтын хувь | ≥ 90% | 2 мин, 10с зогсолт орсон |

**Босго сонгосон үндэслэл:**
- Performance: 200мс нь хэрэглэгчийн харах хурдны ерөнхий стандарт хязгаар тул сонгосон.
- Reliability: серверт зориудаар ~5% алдаа суулгасан тул 8% гэдэг бодит, боломжийн босго.
- Availability: 90% нь 2 минутын цонхонд 10 секундийн зогсолтыг тэвчих боломжтой тооцоолол дээр үндэслэсэн.

**Error budget тооцоо (цагаар):**
2 минутын цонхонд 90% availability гэдэг нь `(1 - 0.90) × 120с = 12 секундийн "эвдрэх эрх"` гэсэн үг.
